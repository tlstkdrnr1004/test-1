shop 요청 흐름 자습서

브라우저에서 버튼을 누르면 서버 안에서 어떤 파일이 어떤 순서로 실행되고, 결과가 다시 화면으로 돌아오는지를 단계별로 따라가는 자습서입니다. 팀원 한 명이 한 흐름씩 맡아서 진행합니다.

이 자습서로 할 수 있는 것
  • shop.zip 을 IntelliJ 로 열고, 요청 하나가 지나가는 파일 순서를 손으로 따라갑니다.
  • 각 파일에서 무엇을 하는 코드인지 확인하고, 작은 수정(과제)을 직접 해 봅니다.
  • 마지막에 4가지 기능(상품 등록, 상품 조회, 회원가입, 장바구니·주문)이 모두 동작하는지 확인합니다.
주의: shop.zip 안에는 이미 완성된 코드가 들어 있습니다. 이 자습서는 빈 파일에서 코드를 처음부터 타이핑하는 방식이 아니라, 완성된 코드를 요청 순서대로 읽고 확인하고 고치는 방식입니다. 설치와 프로젝트 열기는 shop 팀 프로젝트 자습서(1~5장)를 먼저 따라 주세요.

0. 시작 전 준비

  1. shop.zip 을 풀고, build.gradle 이 있는 shop 폴더를 IntelliJ 로 엽니다. (자세한 방법은 기존 자습서 4장)
  2. MySQL 에 shop 데이터베이스가 있어야 합니다. (기존 자습서 2장)
  3. src/main/java/com/shop/ShopApplication.java 의 main 을 실행하고, 브라우저에서 http://localhost:8081 이 열리는지 확인합니다.
기억할 점 이 프로젝트는 Spring Boot 로 만든 웹 서버입니다. 브라우저 주소창에 입력하거나 버튼을 누르면 서버의 컨트롤러가 요청을 받고, 필요한 일은 서비스에 맡기고, 데이터는 리포지토리를 거쳐 DB 에서 가져옵니다. 결과는 HTML 템플릿(화면)으로 돌아갑니다.

1. 한눈에 보는 요청 흐름

거의 모든 기능이 아래 같은 순서로 움직입니다.

브라우저→Controller
요청을 받음→Service
업무 규칙→Repository
DB 읽기·쓰기→Entity
테이블과 연결된 객체
Entity / DTO→Controller 가 Model 에 담음→Thymeleaf 템플릿
templates/*.html→브라우저 화면
이름파일 위치한 줄 설명
Controllersrc/main/java/com/shop/controller"어떤 주소로 요청이 왔는지" 받아서 처리를 시키는 곳
Servicesrc/main/java/com/shop/service실제 업무 규칙(중복 확인, 재고 줄이기, 저장 등)을 하는 곳
Repositorysrc/main/java/com/shop/repositoryDB 에서 찾고 저장하는 일을 맡는 곳
Entitysrc/main/java/com/shop/entityDB 테이블 한 줄과 같은 자바 객체
DTOsrc/main/java/com/shop/dto화면과 주고받는 데이터 상자(입력 폼, 화면 표시용)
Templatesrc/main/resources/templates브라우저에 보여 줄 HTML 화면

2. 흐름 A · 상품 등록 (관리자)

담당 예시: 팀원 1. 상품 등록 화면을 열고, 상품과 사진을 올려 저장하는 흐름입니다.

A-1. 등록 화면 열기 — GET /admin/item/new

  1. 브라우저가 /admin/item/new 를 요청합니다.
  2. ItemController.itemForm 이 빈 입력 상자(ItemFormDto)를 만들어 화면에 넘깁니다.
  3. 화면 파일 templates/item/itemForm.html 이 열립니다.

A-2. 등록 버튼 누르기 — POST /admin/item/new

  1. 입력값과 사진이 서버로 전송됩니다.
  2. ItemController.itemNew 가 받습니다. 먼저 입력값이 빠지지 않았는지(@Valid) 확인하고, 첫 번째 사진이 있는지 확인합니다.
  3. ItemService.saveItem 을 호출합니다. 여기서 ItemFormDto.createItem() 으로 Item 객체를 만들고 itemRepository.save(item) 으로 DB 에 저장합니다.
  4. 사진마다 ItemImgService.saveItemImg 를 호출하고, 그 안에서 FileService.uploadFile 이 사진을 저장 폴더에 씁니다.
  5. 성공하면 redirect:/ 로 메인 화면으로 돌아갑니다.
저장 위치 사진은 프로젝트 안 shop-uploads/item 폴더에 저장됩니다. 이 폴더는 처음에 없어도 업로드할 때 자동으로 만들어집니다. (설정: application.properties 의 itemImgLocation)

3. 흐름 B · 상품 상세 보기 (고객)

담당 예시: 팀원 2. 메인 화면에서 상품을 눌렀을 때 상세 화면이 나오는 흐름입니다.

  1. 브라우저가 GET /item/{itemId} 를 요청합니다.
  2. ItemController.itemDtl 이 itemId 를 받아 ItemService.getItemDtl 을 호출합니다.
  3. 서비스는 itemImgRepository.findByItemIdOrderByIdAsc 로 사진 목록을, itemRepository.findById 로 상품을 가져옵니다.
  4. 가져온 값을 ItemFormDto 에 모아 item 이라는 이름으로 화면에 넘깁니다.
  5. templates/item/itemDtl.html 이 그려집니다.

B-1. 과제

4. 흐름 C · 회원가입

담당 예시: 팀원 3. 회원가입 폼을 제출해서 계정이 DB 에 저장되는 흐름입니다.

  1. GET /members/new → MemberController.memberForm → member/memberForm.html
  2. POST /members/new → MemberController.newMember. 입력값이 잘못되면 member/memberForm 으로 되돌아갑니다.
  3. Member.createMember(...) 로 엔티티를 만들고, 비밀번호는 암호화합니다.
  4. MemberService.saveMember 가 같은 이메일이 있는지 확인한 뒤 저장합니다. 중복이면 예외가 나고 화면에 메시지가 나옵니다.

C-1. 과제

5. 흐름 D · 장바구니와 주문

로그인한 뒤에 할 수 있습니다. 이 흐름은 화면 대신 JSON(데이터 묶음)으로 주고받습니다.

  1. 장바구니 담기: 브라우저의 자바스크립트가 POST /cart 로 상품 번호와 수량을 JSON 으로 보냅니다. CartController.order 가 받아 CartService.addCart 를 호출하고, 이미 담긴 상품이면 수량만 늘립니다.
  2. 장바구니 보기: GET /cart → CartController → CartService.getCartList → cart/cartList.html
  3. 주문하기: POST /order 가 JSON 을 받으면 OrderController.order 가 처리하고, OrderService 가 주문과 주문 상품을 저장하면서 재고를 줄입니다. 재고가 모자라면 OutOfStockException 이 나옵니다.

7. 자주 막히는 곳

증상원인해결
상품 등록 때 FileNotFoundException앱을 프로젝트 폴더 밖에서 실행했거나, 프로젝트 폴더에 쓰기 권한이 없음IntelliJ 에서 shop 프로젝트 폴더를 열고 실행
상품 등록 후 메인에 사진이 안 보임브라우저 캐시 또는 사진 파일이 없음shop-uploads/item 에 파일이 있는지 확인 후 새로고침
회원가입이 되지 않음이메일 중복 또는 입력 형식 오류화면의 빨간 메시지 확인
장바구니 담기 버튼이 반응하지 않음로그인하지 않음먼저 로그인
Communications link failureMySQL 이 꺼져 있음MySQL 서비스를 켜고 다시 실행

팀장흐름 A (상품 등록) 과 전체 점검체크리스트 전체 확인, PR 리뷰
팀원 1흐름 B (상품 상세)상세 화면과 없는 상품 처리 확인
팀원 2흐름 C (회원가입)중복 가입과 암호화 확인
팀원 3흐름 D (장바구니·주문)담기·주문·재고 확인

팀원은 각자 브랜치를 만들어 작업하고, 끝나면 PR 을 올립니다. 기존 자습서 7~10장의 푸시·PR·충돌 해결 방법을 따릅니다.
