shop 심화 자습서

JPA(데이터 관리), OAuth2(구글 로그인), AWS S3(파일 저장), CI/CD(자동 테스트·배포), Spring AI(LLM 연동)를 shop 프로젝트에 붙이는 순서를 설명합니다. 기본 흐름은 요청 흐름 자습서와 설치·Git 자습서를 먼저 끝낸 뒤 진행하세요.

이 자습서의 범위 (중요)
  • 이 문서는 설명 문서입니다. shop 프로젝트의 소스 코드와 의존성(build.gradle)은 이 문서로 바뀌지 않습니다.
  • 프로젝트는 Spring Boot 3.3.2 기준입니다. 참고 저장소(책 예제)는 Spring Boot 4.0.1 기준이라 코드가 그대로 맞지 않는 부분이 있습니다. 각 장에 차이를 적었습니다.
  • 구글 로그인, AWS, OpenAI(또는 OpenRouter)는 본인 계정과 키가 있어야 실행됩니다. 이 문서를 만든 환경에서는 계정 연결과 실제 실행을 확인하지 못했습니다.
  • AWS 배포와 LLM 호출은 돈이 나갑니다. 사용 후 반드시 정리하세요 (5장, 7장).

표시 읽는 법

저장소 확인 이 프로젝트 파일에서 직접 확인한 내용입니다.
계정 필요 본인 계정이나 키가 있어야 하며, 이 문서에서는 실행을 확인하지 않았습니다.
설명 예시 따라 하기 쉽게 쓴 예제입니다. 프로젝트에 넣은 뒤 테스트로 확인하세요.

1. JPA 로 데이터 다루기 (복잡한 SQL 없이)

이 장은 shop 프로젝트에서 이미 쓰는 JPA 기능을 더 깊이 다룹니다. 새 SQL 을 직접 쓰지 않고 메서드 이름과 객체 탐색으로 해결하는 방법입니다.

1-1. 리포지토리 기본 메서드 저장소 확인

ItemRepository 는 JpaRepository<Item, Long> 를 상속합니다. 이 인터페이스만으로 아래 메서드를 쓸 수 있습니다.

메서드하는 일반환 타입
save(entity)없으면 INSERT, 있으면 UPDATE저장된 엔티티
findById(id)기본키로 한 건 조회Optional<T>
findAll()전체 조회List<T>
deleteById(id)기본키로 삭제없음
count()전체 개수long

1-2. 메서드 이름으로 조회 (쿼리 작성 없이) 설명 예시

메서드 이름이 곧 WHERE 조건이 됩니다. 아래 규칙을 따르세요.

메서드 이름 규칙대응하는 SQL 조건
findByItemNm(String itemNm)WHERE item_nm = ?
findByItemNmContaining(String keyword)WHERE item_nm LIKE '%keyword%'
findByPriceGreaterThan(int price)WHERE price > ?
findByStockNumberLessThan(int n)WHERE stock_number < ?
findByItemSellStatusOrderByPriceDesc(ItemSellStatus s)WHERE item_sell_status = ? ORDER BY price DESC
// 예시: ItemRepository 인터페이스 안에 메서드 선언만 추가합니다. 구현 코드는 쓰지 않습니다.
List<Item> findByItemNmContaining(String keyword);
List<Item> findByPriceGreaterThan(int price);
확인 방법 테스트 클래스에서 @Autowired ItemRepository itemRepository; 를 선언하고, 상품 2개를 저장한 뒤 메서드를 호출해 개수를 assertEquals 로 확인합니다. 테스트 클래스는 src/test/java/com/shop/repository/ 에 만듭니다.

1-3. 페이징과 정렬 설명 예시

import org.springframework.data.domain.Page;
import org.springframework.data.domain.PageRequest;
import org.springframework.data.domain.Sort;

// 페이지 번호는 0부터 시작합니다. 한 페이지에 10건, 가격 높은 순
PageRequest pageable = PageRequest.of(0, 10, Sort.by("price").descending());
Page<Item> page = itemRepository.findAll(pageable);
long total = page.getTotalElements();   // 전체 건수
List<Item> items = page.getContent();  // 현재 페이지 목록

shop 프로젝트는 이미 ItemRepositoryCustom 에서 QueryDSL 로 검색과 페이징을 합니다 (저장소 확인). 메서드 이름 방식으로 충분한 경우에는 이 방식을 먼저 쓰세요.

1-4. 한 번에 가져오기: @EntityGraph 설명 예시

연관된 엔티티를 나중에 하나씩 조회하면 SQL 이 여러 번 나갑니다(N+1 문제). @EntityGraph 는 필요한 연관 데이터를 한 번에 가져옵니다.

@EntityGraph(attributePaths = {"item"})
List<ItemImg> findByItemId(Long itemId);

이 프로젝트의 ItemImgRepository 에는 findByItemIdOrderByIdAsc 가 있습니다 (저장소 확인). 상품 목록 화면에서 이미지가 많아지면 이 방식을 검토하세요.

1-5. 지연 로딩과 트랜잭션 규칙

  • 연관 관계는 fetch = FetchType.LAZY 로 두는 것이 이 프로젝트의 기본입니다 (저장소 확인: CartItem, OrderItem, Order).
  • 조회만 하는 메서드는 @Transactional(readOnly = true) 를 붙입니다 (저장소 확인: ItemService.getItemDtl).
  • 화면(Thymeleaf)에서 연관 객체를 꺼낼 때 LazyInitializationException 이 나면, 서비스에서 필요한 값을 DTO 에 담아 돌려주세요.

// build.gradle 의 dependencies 블록 (버전은 Maven Central 에서 확인한 값으로 씁니다)

2-4. 서비스 코드 설명 예시

package com.shop.service;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.model.ChatModel;
import org.springframework.stereotype.Service;

@Service
public class ItemDescriptionAiService {

    private final ChatClient chatClient;

    // ChatModel 은 Spring AI 가 자동으로 만들어 주는 빈입니다. 생성자로 주입받습니다.
    public ItemDescriptionAiService(ChatModel chatModel) {
        this.chatClient = ChatClient.builder(chatModel).build();
    }

    // 상품명을 받아서 설명 문장을 만들어 돌려줍니다.
    public String suggestDescription(String itemName) {
        return chatClient.prompt()
                .user("다음 상품을 한국어로 두 문장 소개해 주세요: " + itemName)
                .call()
                .content();
    }
}

2-6. 2장 과제

3. OAuth2 구글 로그인 계정 필요

목표: "구글로 로그인" 버튼으로 구글 계정 인증을 받고, 최초 로그인 시 회원 정보를 shop 의 member 테이블에 저장합니다.

3-1. Google Cloud 에서 OAuth 클라이언트 만들기 계정 필요

  1. Google Cloud Console(console.cloud.google.com) 에 로그인하고 프로젝트를 만듭니다.
  2. APIs & Services → OAuth consent screen 에서 외부(External) 사용자 유형을 고르고, 앱 이름과 본인 이메일을 입력합니다.
  3. APIs & Services → Credentials → Create credentials → OAuth client ID 를 고릅니다.
  4. Application type 은 Web application 입니다.
  5. Authorized redirect URIs 에 다음을 추가합니다.
    http://localhost:8081/login/oauth2/code/google
  6. 생성 후 나오는 Client ID 와 Client secret 을 복사해 둡니다. 이 값은 파일에 적지 않고 환경변수로 씁니다.
주의 리디렉션 주소의 포트(8081)와 경로(/login/oauth2/code/google)가 한 글자라도 다르면 로그인이 실패합니다.

3-2. 의존성 추가 저장소 확인

implementation 'org.springframework.boot:spring-boot-starter-oauth2-client'

이 스타터는 Spring Boot 3.3.2 에서도 같은 이름으로 씁니다.

3-3. 설정 파일 저장소 확인

책 저장소의 설정 키 이름과 같은 구조입니다. 값은 환경변수로 넣습니다.

spring.security.oauth2.client.registration.google.client-id=${GOOGLE_CLIENT_ID}
spring.security.oauth2.client.registration.google.client-secret=${GOOGLE_CLIENT_SECRET}
spring.security.oauth2.client.registration.google.scope=email,profile

3-4. 보안 설정에 추가 설명 예시

shop 의 SecurityConfig 는 이미 폼 로그인을 쓰고 있습니다. 구글 로그인은 같이 쓰는 방식으로 추가하세요. 기존 formLogin() 을 지우지 마세요.

// SecurityConfig 의 filterChain 메서드 안, 기존 설정 아래에 추가합니다.
http.oauth2Login(oauth -> oauth
        .loginPage("/members/login")                 // 기존 로그인 페이지 재사용
        .defaultSuccessUrl("/", true)                // 로그인 성공 후 이동할 주소
        .userInfoEndpoint(info -> info
                .userService(oAuth2UserService)));   // 아래 3-5 의 서비스

메서드 이름과 반환 타입은 Spring Security 버전에 따라 조금 다를 수 있습니다. 컴파일 오류가 나면 해당 버전의 공식 문서 예제를 같이 보세요.

3-5. 최초 로그인 시 회원 저장 설명 예시

@Service
@RequiredArgsConstructor
public class OAuth2UserService extends DefaultOAuth2UserService {

    private final MemberRepository memberRepository;

    @Override
    public OAuth2User loadUser(OAuth2UserRequest request) throws OAuth2AuthenticationException {
        OAuth2User user = super.loadUser(request);
        String email = user.getAttribute("email");   // 구글이 돌려주는 이메일
        String name  = user.getAttribute("name");    // 구글이 돌려주는 이름

        // 같은 이메일이 없으면 새 회원으로 저장합니다. (email 은 member 테이블에서 unique)
        if (memberRepository.findByEmail(email) == null) {
            // 실제 저장 로직은 Member 엔티티의 생성 메서드(createMember 계열)를 사용하세요.
            // 구글 로그인 회원은 비밀번호가 없으므로 Member 의 password 설정 방식을 팀에서 정하세요.
        }
        return user;
    }
}
팀 결정 필요 구글 회원의 password 컬럼 값과 role 기본값은 팀에서 먼저 정하세요. 폼 로그인 회원과 충돌하면 로그인 오류가 납니다.

3-6. 확인 방법

  1. 앱을 실행하고 로그인 페이지에서 "구글로 로그인"을 누릅니다.
  2. 구글 계정을 고르고 동의하면 메인 화면으로 돌아옵니다.
  3. SELECT member_id, name, email, role FROM member; 로 회원이 생겼는지 확인합니다.
  4. 로그아웃 후 다시 로그인해서 중복 회원이 생기지 않는지 확인합니다.

3-7. 3장 과제

4. AWS S3 에 이미지 저장 계정 필요

현재 shop 은 상품 이미지를 프로젝트 안 shop-uploads/item 폴더에 저장합니다 (저장소 확인: FileService.uploadFile). S3 는 서버 밖에 저장하는 방식입니다. 배포 서버를 여러 대 두거나, 서버를 다시 올려도 파일을 유지하려면 S3 를 씁니다.

4-1. AWS 준비 계정 필요

  1. AWS 콘솔에서 S3 버킷을 만듭니다. 리전은 ap-northeast-2(서울)를 권장합니다.
  2. 버킷의 Block Public Access 는 켠 채로 둡니다. 파일 접근은 서버가 담당합니다.
  3. IAM → Users 에서 실습 전용 사용자를 만들고, 권한은 해당 버킷에만 쓰기·읽기로 제한합니다.
  4. 사용자의 Access key 를 만들고, 키 ID 와 Secret 을 안전한 곳에 복사합니다. 파일에 적지 마세요.

4-2. 의존성과 설정 설명 예시

// Maven Central 에서 최신 버전을 확인해 씁니다 (책 저장소는 2.41.31 을 사용)
implementation 'software.amazon.awssdk:s3:<버전>'
cloud.aws.region=${AWS_REGION}
cloud.aws.s3.bucket=${AWS_S3_BUCKET}

책 저장소의 application.yml 은 cloud.aws.region, cloud.aws.s3.bucket 키를 씁니다 (저장소 확인). 다만 책 저장소의 빌드 파일에는 software.amazon.awssdk:s3 만 있고 별도 Spring Cloud 라이브러리는 없습니다. 그래서 설정 키 이름은 참고만 하고, 실제 빈 생성은 AWS SDK 코드로 직접 작성해야 합니다.

4-3. 로컬 저장과 S3 저장을 전환하기 (@Profile) 설명 예시

public interface FileStorage {
    String upload(String originalName, byte[] data) throws Exception;
}

@Service
@Profile("local")                     // application-local.properties 를 쓸 때만 동작
public class LocalFileStorage implements FileStorage {
    public String upload(String originalName, byte[] data) throws Exception {
        // 기존 FileService 로직을 그대로 사용합니다.
        return "local-file-name";
    }
}

@Service
@Profile("prod")                      // 배포 환경에서만 동작
public class S3FileStorage implements FileStorage {
    // S3Client 를 주입받아 putObject 로 업로드합니다. 구현은 AWS SDK 문서 예제를 따릅니다.
    public String upload(String originalName, byte[] data) throws Exception {
        throw new UnsupportedOperationException("S3 구현 후 제거");
    }
}

실행 시 프로필은 --spring.profiles.active=local 로 지정합니다. 위 코드의 S3 구현은 골격입니다. 실제 업로드 코드는 AWS SDK 공식 예제로 채우고, 테스트에서 실제 버킷에 쓰지 않도록 주의하세요.

4-4. 4장 과제

5. AWS 배포 (Elastic Beanstalk) 계정 필요 과금 주의

책 저장소는 Elastic Beanstalk 에 JAR 를 올리는 방식을 씁니다. 이 장은 개념과 순서만 설명하고, 실제 환경 생성은 계정 준비가 끝난 뒤 진행하세요.

비용 경고 Elastic Beanstalk 환경은 EC2 인스턴스와 로드 밸런서를 만들며, 실행하는 동안 계속 과금됩니다. 실습이 끝나면 환경을 Terminate 하세요. 남은 S3 버킷과 IAM 키도 확인해서 지우세요 (7장).

5-1. 순서

  1. AWS 콘솔에서 Elastic Beanstalk → Create application. 플랫폼은 Java 를 고르고, 버전은 프로젝트가 쓰는 Java 버전에 맞춥니다. (이 프로젝트는 빌드 JDK 25, 바이트코드 출력 21 입니다 (저장소 확인: build.gradle))
  2. 환경 이름을 정합니다. 책 저장소 예: Springboot-developer-env. 팀은 자기 이름을 붙여 바꾸세요.
  3. 샘플 JAR 로 환경이 올라오는지 확인합니다.
  4. JAR 를 직접 업로드하거나, 6장의 GitHub Actions 로 자동 배포합니다.
  5. 접속 주소로 응답이 오는지 확인합니다.

5-2. 배포 후 확인

  • Elastic Beanstalk 콘솔의 환경 상태가 Ok 인지 확인합니다.
  • 이벤트 탭에서 실패 로그를 확인합니다.
  • 브라우저에서 환경의 URL 로 메인 화면을 엽니다.

6. CI/CD (GitHub Actions 자동 테스트·배포)

shop 은 이미 CI(자동 테스트)가 있습니다. 파일은 .github/workflows/shop-ci.yml 입니다 (저장소 확인). 여기에 배포 단계를 추가하는 방법을 설명합니다.

6-1. 지금 있는 CI 의 역할

  • PR 과 main push 때 build-and-test 작업이 돌고, ./gradlew test 를 실행합니다.
  • 테스트 결과를 PR 체크(✔/✘)로 보여 줍니다.

6-2. 책 저장소 워크플로의 주의점 저장소 확인

책 저장소의 cicd.yml 은 on: push 로만 되어 있어서, 어떤 브랜치에 push 해도 배포가 돕니다. 팀 프로젝트에서는 이렇게 두면 작업 브랜치마다 운영 서버가 바뀝니다. 배포는 main 에서만 돌리세요.

6-3. 배포 단계 추가 계정 필요 설명 예시

아래는 shop-ci.yml 에 배포 작업을 따로 추가하는 예입니다. 기존 build-and-test 는 그대로 두세요.

  deploy:
    needs: build-and-test
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          distribution: corretto
          java-version: '25'
      - name: 빌드
        run: |
          chmod +x gradlew
          ./gradlew bootJar -x test
      - name: Elastic Beanstalk 배포
        uses: einaregilsson/beanstalk-deploy@v22
        with:
          aws_access_key: ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws_secret_key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          application_name: shop-app
          environment_name: shop-app-env
          version_label: shop-${{ github.run_number }}
          region: ap-northeast-2
          deployment_package: build/libs/shop-0.0.1-SNAPSHOT.jar
  • deployment_package 의 JAR 파일명은 build/libs 에 실제로 생긴 이름과 같아야 합니다. 빌드 후 ls build/libs 로 확인하세요.
  • 액션 버전(@v22 등)은 GitHub Marketplace 에서 최신 버전을 확인하세요. 이 문서는 버전이 바뀌었는지 검증하지 않았습니다.
  • Secrets 는 저장소 Settings → Secrets and variables → Actions 에 등록합니다. 워크플로 파일에 키를 쓰지 않습니다.

6-4. 6장 확인 방법

  1. 작업 브랜치에서 PR 을 만들면 build-and-test 만 돌고 배포는 안 돌아야 합니다.
  2. PR 을 main 에 머지하면 deploy 가 돌고, Actions 화면에서 성공을 확인합니다.
  3. Elastic Beanstalk 콘솔에서 새 버전 라벨(shop-번호)이 배포됐는지 확인합니다.

8. 팀 역할과 진행 순서

순서장담당 예시끝났다는 증거

56장 CI/CD팀장main 머지 후 deploy 성공 캡처

순서가 중요한 이유 3장(구글 로그인)은 회원 테이블 구조를 알아야 하므로 1장 다음입니다. 5장(배포)은 로그인과 AI 기능이 로컬에서 먼저 돌아야 합니다. CI/CD 는 마지막에 붙입니다.

9. 이 문서의 한계 (반드시 읽기)

  • 검증하지 않은 것: 구글 로그인 화면, AWS 콘솔 메뉴 이름, Spring AI 와 OpenRouter 설정, GitHub Actions 배포 단계는 이 문서를 만든 환경에서 실제로 실행하지 않았습니다. 콘솔 화면은 자주 바뀌므로 메뉴 이름이 다를 수 있습니다.
  • 버전: Spring AI, AWS SDK, 배포 액션의 버전은 여기 적힌 값을 그대로 쓰지 말고, 공식 문서나 Maven Central 에서 Spring Boot 3.3.2 와 맞는 값을 확인하세요.
  • 프로젝트와의 차이: 책 예제는 Spring Boot 4.0.1 과 Java 25 툴체인을 씁니다. shop 은 Spring Boot 3.3.2 와 release 21 입니다. 책 코드를 그대로 복사하면 컴파일이 안 될 수 있습니다.
  • 이 문서는 프로젝트 코드를 바꾸지 않았습니다. 실제 적용은 팀이 별도 브랜치에서 PR 로 진행합니다.
